| `int main() { ... }` | Главная функция: выполнение программы начинается с неё. Фигурные скобки ограничивают тело функции или другого блока. |

| `.` и `->` | `object.field` обращается к полю объекта; `pointer->field` — к полю объекта через указатель. |
| `::` | Уточнение области имён: `std::list` — тип `list` из стандартной библиотеки; `Base::insert` — метод типа `Base`. |

**Контейнер** — объект для хранения нескольких значений. **Итератор** — объект, которым можно указывать на элемент контейнера и переходить к следующему. **Инвариант** — свойство, которое должно оставаться истинным после каждой разрешённой операции. **Стек** работает по правилу «последним положили — первым достали». **Дек** допускает добавление и удаление с обоих концов.

Для оценок сложности `n` обозначает число элементов. `O(1)` — число действий не растёт вместе с `n`; `O(n)` — растёт примерно пропорционально `n`; `O(n²)` — примерно пропорционально квадрату `n`. **Амортизированное `O(1)`** допускает редкую дорогую операцию, если на длинной последовательности средняя стоимость одной операции остаётся ограниченной константой.

## Задание 2.1. Упорядоченный список

**Файл:** `src/task2_1.cpp`.

### Смысл условия

Нужно построить `Ordered_list<T>` на основе `std::list<T>`, дать ему методы `insert(const T&)`, `remove(const T&)`, `begin() const` и `end() const` и гарантировать, что элементы всегда идут в неубывающем порядке. Условие также спрашивает, каким должно быть отношение между обычным списком и упорядоченным.

`std::list<T>` — готовый двусвязный список из стандартной библиотеки. «Неубывающий» означает, что каждый следующий элемент не меньше предыдущего: `1, 2, 2, 5` подходит.

### Как закрыта возможность испортить порядок

```cpp
template <class T>
class Ordered_list : private std::list<T> {
    using Base = std::list<T>;
public:
    using const_iterator = typename Base::const_iterator;
    // ...
};
```

`template <class T>` делает класс шаблонным. `private std::list<T>` означает **закрытое наследование**: внутри `Ordered_list` доступны возможности обычного списка, но вызывающий код не получает его изменяющие методы. `using Base = ...` вводит короткое имя для базового типа. `typename` сообщает компилятору, что зависящее от `T` имя `Base::const_iterator` является названием типа.

Наружу выдаются только **константные итераторы**. `begin()` указывает на начало, `end()` — на позицию *после* последнего элемента. Читатель может пройти по списку, но не может заменить `2` на `100` через итератор.

### Вставка и её правильность

```cpp
auto it = Base::cbegin();
while (it != Base::cend() && !(value < *it)) ++it;
Base::insert(it, value);
```

`auto` просит компилятор вывести тип переменной `it`. `cbegin()` и `cend()` дают константные итераторы. `it != Base::cend()` проверяет, не закончился ли список. `value < *it` спрашивает, меньше ли новое значение текущего; `!` меняет ответ на противоположный. Таким образом, цикл пропускает элементы, не превышающие новое значение. `++it` переводит итератор к следующему элементу.

`insert(it, value)` вставляет значение **перед** текущей позицией. Если список `[1, 2, 4, 5]`, а добавляется `3`, цикл проходит `1` и `2`, останавливается на `4`, затем вставляет `3` перед `4`. Результат `[1, 2, 3, 4, 5]`. Равные элементы цикл тоже пропускает, поэтому повторное значение встаёт после существующих равных.

Почему порядок гарантирован: до точки вставки стоят элементы `<= value`, а после неё — элементы `> value`. Значит, вставка не создаёт нарушения ни слева, ни справа. Поиск позиции занимает `O(n)`; вставка в уже найденную позицию связного списка — `O(1)`. Весь `insert` — `O(n)`.

### Удаление, итераторы и ответ на вопрос

`Base::remove(value)` удаляет **все** элементы, равные `value`, за `O(n)`. Например, `[1, 2, 2, 4, 5]` после `remove(2)` превращается в `[1, 4, 5]`. Для этой реализации тип `T` должен поддерживать `<` для упорядочивания и `==` для удаления.

**Ответ о связи классов:** упорядоченный список **реализован с помощью** обычного списка, но не должен предоставлять его произвольные операции изменения как часть своего открытого интерфейса. Поэтому в программе применяется закрытое наследование. Возможен и вариант с полем `std::list<T>` внутри `Ordered_list` — композиция. Публичное наследование здесь нарушило бы требование «всегда упорядочен»: клиент получил бы, например, возможность вставлять без проверки нужного места.

## Задание 2.2. Дек на динамическом массиве

**Файл:** `src/task2_2.cpp`.

### Смысл условия и обозначения

Дек позволяет работать с **двумя концами** последовательности. `Push_Back` добавляет сзади, `Pop_Back` удаляет сзади, `Push_Front` добавляет спереди, `Pop_Front` удаляет спереди. Требуется амортизированная стоимость `O(1)` и закрытый метод `Reallocate` для увеличения и уменьшения массива.

В классе `data_` — сам массив; `capacity_` — сколько ячеек выделено; `size_` — сколько элементов реально хранится; `first_` — физический индекс первого элемента. `std::unique_ptr<T[]>` автоматически освобождает выделенный массив при уничтожении объекта. `std::make_unique<T[]>(minimum)` выделяет начальные 4 ячейки. Тип `T` здесь должен иметь конструктор по умолчанию и поддерживать присваивание.

### Почему массив сделан кольцевым

Если первый элемент всегда хранить в `data_[0]`, вставка спереди потребовала бы сдвига всего массива. Вместо этого индекс начала можно менять. Физическое место логического элемента номер `i` вычисляется так:

```cpp
(first_ + i) % capacity_
```

Оператор `%` берёт остаток от деления и «заворачивает» индекс с конца массива в его начало. Например, при ёмкости 8 и `first_ == 6` четыре элемента располагаются в ячейках `6, 7, 0, 1`, но логически идут подряд.

Для `Push_Front` начало сдвигается назад по кольцу:

```cpp
first_ = (first_ + capacity_ - 1) % capacity_;
```

При `Push_Back` новое значение записывается в `(first_ + size_) % capacity_`. Удаления берут крайнее значение и обновляют `first_` либо `size_`. Пока ёмкости хватает, каждая операция делает постоянное число действий.

### Что делает `reallocate`

```cpp
auto next = std::make_unique<T[]>(new_capacity);
for (std::size_t i = 0; i < size_; ++i)
    next[i] = std::move(data_[(first_ + i) % capacity_]);
data_ = std::move(next);
capacity_ = new_capacity;
first_ = 0;
```

`new_capacity` — новая ёмкость. Цикл переносит элементы **в логическом порядке**, даже если старое кольцо было разделено между концом и началом массива. `std::move` разрешает переместить значение или владение ресурсом вместо обычного копирования, когда тип это умеет. После переноса элементы лежат подряд, поэтому `first_` становится нулём. Метод находится до `public:`, следовательно, извне он закрыт. Если хранится `n` элементов, перераспределение занимает `O(n)`.

### Ответ о росте, уменьшении и амортизации

| Когда | Действие |
| --- | --- |
| Перед вставкой массив заполнен: `size_ == capacity_` | Удвоить ёмкость |
| После удаления заполнено не более четверти: `size_ <= capacity_ / 4` | Уменьшить ёмкость вдвое |
| Ёмкость уже равна 4 | Не уменьшать дальше |

Порог уменьшения в четверть нужен, чтобы добавление и удаление около половины массива не вызывали бесконечные чередующиеся перераспределения. После расширения с `C` до `2C` нужно выполнить порядка `C` новых вставок до следующего расширения. После уменьшения также требуется много операций до следующего изменения размера. Эти дешёвые операции «оплачивают» редкий перенос `O(C)`. Поэтому последовательность из `m` операций стоит `O(m)` суммарно, или `O(1)` **амортизированно** на операцию. Отдельная операция, вызвавшая `reallocate`, всё же стоит `O(n)`.

`throw std::out_of_range("empty deque")` означает «выбросить ошибку», если программа пытается удалить элемент из пустого дека. В `main` пример показывает увеличение ёмкости с 4 до 8 и последующее уменьшение до 4.

## Задание 2.3. Кольцевой список студентов с несколькими ссылками

**Файл:** `src/task2_3.cpp`.

### Смысл условия

У каждого студента есть ФИО, дата рождения и группа. Один и тот же набор студентов нужно уметь обходить в порядке выбранного ключа **за один проход**. Список должен быть кольцевым и начинаться с фиктивного узла — «болванчика». Здесь речь о нескольких **связях между узлами**, а не о параллельно работающих потоках программы.

### Что означают структуры и указатели

`struct Student` объединяет три поля. `std::string` — строка; `int` — целое число. `enum class Key` задаёт три допустимых ключа `Name`, `Birth`, `Group`. Значение `Count` используется для определения числа ключей, но не для вывода.

`Node*` — указатель на узел. Каждый узел хранит студента и массив из трёх указателей:

```cpp
std::array<Node*, keys> next{};
```

`next[0]` ведёт к следующему по ФИО, `next[1]` — по дате рождения, `next[2]` — по группе. Студент при этом хранится **один раз**. Только направления перехода отличаются.

`sentinel_` — фиктивный узел. В пустом списке каждая его ссылка указывает на него самого. В непустом списке последний реальный узел каждой цепочки указывает обратно на `sentinel_`. Это и делает список кольцевым.

### Как поддерживаются три порядка

`insert(Student value)` создаёт новый узел выражением `new Node{...}`. `new` выделяет для него память, фигурные скобки задают начальные поля. Затем цикл `for` по трём ключам находит подходящее место в **каждой** цепочке и меняет ссылки:

```cpp
node->next[k] = before->next[k];
before->next[k] = node;
```

Первая строка направляет новый узел на бывшего последователя; вторая направляет предыдущий узел на новый. Если сначала поменять только вторую ссылку, можно временно потерять путь к остальной цепочке — поэтому порядок действий важен.

Функция `less` сравнивает студентов. `std::tie(...)` собирает несколько полей в последовательность для сравнения: например, при сортировке по ФИО сначала сравниваются имена, затем даты, группы и порядковый номер вставки `serial`. При равенстве основного ключа это даёт однозначный порядок. Дата представлена как `YYYY-MM-DD`: для корректных дат такого формата обычное сравнение строк совпадает с порядком дат.

### Почему вывод требует один проход

`print(Key key)` выбирает нужное число `k`, начинает с `sentinel_.next[k]` и следует только по ссылкам `next[k]`, пока не вернётся к фиктивному узлу. Поэтому каждый студент посещается ровно один раз, вывод стоит `O(n)`. Вставка в худшем случае просматривает все узлы в каждой из трёх цепочек. Так как ключей ровно три, это тоже `O(n)`.

Деструктор `~StudentList()` вызывается при уничтожении списка. Он проходит одну цепочку и выполняет `delete` для каждого настоящего узла. Проходить все три цепочки с `delete` нельзя: это одни и те же объекты, и произошло бы повторное удаление. Строки `StudentList(const StudentList&) = delete` и аналогичная для присваивания запрещают копирование класса: иначе два списка владели бы одними и теми же указателями.

**Ответ на вопрос условия:** дополнительные ссылки создают отдельный готовый порядок обхода для каждого ключа. Кольцо с «болванчиком» даёт единое условие завершения и упрощает работу с концами списка.

## Задание 3.1. Двусвязный список внутри одного массива

**Файл:** `src/task3_1.cpp`.

### Что требуется

Нужно вставлять и удалять узел в произвольном месте за `O(1)`, **если место уже найдено**, но хранить узлы в массиве. Для свободных ячеек нельзя заводить второй массив или список вне основного массива.

### Индексы вместо адресов

В обычном двусвязном списке узел хранит указатели на соседей. Здесь `Slot` хранит целочисленные `prev` и `next` — **номера ячеек массива**. Значение `-1` означает «соседа нет». Поля `head_` и `tail_` хранят индексы первого и последнего узлов.

Например, логический список `10 → 20 → 30` может занимать ячейки массива `5 → 1 → 7`. Физическое расположение ячеек не обязано совпадать с порядком списка. При расширении массив может переехать в другое место памяти, но индексы 5, 1 и 7 сохраняют смысл.

### Как стек свободных ячеек помещается в тот же массив

`free_` хранит индекс верхней свободной ячейки. Пока ячейка свободна, её поле `next` означает **следующую свободную ячейку**, а не следующего участника списка. Например, `free_ = 2`, `slots_[2].next = 5`, `slots_[5].next = -1` задаёт стек `2 → 5 → конец`.

`acquire` снимает одну свободную ячейку со стека и записывает в неё значение. После снятия служебные `next` и `prev` сбрасываются в `-1`: это нужно, чтобы старая ссылка стека свободных мест не попала в рабочий список. `erase` делает обратное: отсоединяет узел от соседей, отмечает его свободным и кладёт в вершину стека. `used` — логическое поле, отличающее занятую ячейку от свободной.

### Почему известное место даёт `O(1)`

`insert_after(position, value)` и `insert_before(position, value)` меняют постоянное число связей соседних узлов. `erase(id)` тоже меняет только связи двух соседей и вершину стека свободных ячеек. Поиск `find(value)` — другое действие: он идёт от `head_` по `next` и в худшем случае занимает `O(n)`. Условие специально исключает время поиска.

`check(id)` проверяет, что индекс существует и ячейка занята. Иначе выбрасывается `std::out_of_range`. Если элемент уже удалён, его старым индексом пользоваться нельзя: ту же ячейку позже могут выдать новому элементу.

### Точная оговорка о расширении

Если свободных ячеек нет, `grow` выделяет массив вдвое больше, переносит старые ячейки и добавляет новые в тот же стек свободных мест. Перенос занимает `O(n)`. Поэтому **в этой конкретной реализации** вставка при наличии места занимает `O(1)`, отдельная вставка с расширением — `O(n)`, а вставка в среднем по длинной серии операций — `O(1)` амортизированно. Удаление по известному индексу остаётся `O(1)`.

`new Slot[new_capacity]` создаёт массив; `delete[] slots_` уничтожает старый. Другого массива, сохраняемого в структуре данных, нет: при расширении на короткое время одновременно существуют старый и новый массив для переноса. Для шаблонного `T` в этом примере нужен конструктор по умолчанию и присваивание.

## Задание 3.2. Сортировка выбором с двумя стеками

**Файл:** `src/task3_2.cpp`.

### Что требуется и какие операции разрешены

Исходные числа уже лежат в стеке. На каждом шаге нужно выбрать максимальное среди ещё не отсортированных, используя второй стек. Алгоритм может работать с последовательностью только через `PUSH` (положить на верх), `POP` (снять верх и получить значение), `CREATE` (создать пустой стек) и `EMPTY` (проверить, пуст ли стек). Посмотреть произвольный элемент глубоко внутри стека нельзя.

Класс `Stack` — небольшая оболочка над `std::stack<int>`. Внутри его `Pop` используются методы стандартного стека `top()` и `pop()`, но **сортирующая функция** видит только четыре разрешённые операции оболочки. `std::vector` в `main` нужен лишь для записи демонстрационных чисел перед началом сортировки.

### Один шаг выбора максимума

Пусть в `input` осталось `remaining` неотсортированных элементов, а внизу `selected` уже лежат выбранные максимумы. Алгоритм `remaining` раз делает `input.Pop()` и `selected.Push(value)`, одновременно запоминая наибольшее значение в обычной переменной `maximum`. Затем ровно `remaining` раз снимает только что перенесённые числа с `selected` и возвращает их в `input`, **кроме одной копии `maximum`**. После этого кладёт `maximum` на верх `selected`.

Переменные `first` и `skipped` имеют тип `bool`, то есть содержат «истина» или «ложь». `first` позволяет правильно инициализировать максимум даже при отрицательных числах. `skipped` гарантирует, что при повторениях за проход исключена только одна копия максимума.

Почему нижняя отсортированная часть `selected` не повреждается? Алгоритм знает число временно перенесённых элементов `remaining` и снимает обратно ровно их. Более старые выбранные максимумы остаются ниже.

### Как получается порядок и сколько это стоит

Если значения `4, -2, 7, 4, 1`, выбранные максимумы попадают в `selected` по очереди `7, 4, 4, 1, -2`. Значит, снизу вверх стек содержит `[7, 4, 4, 1, -2]`, а его `POP` выдаёт возрастающую последовательность `-2, 1, 4, 4, 7`.

На первом проходе обрабатывается `n` чисел, на втором `n-1`, затем `n-2` и так далее. Сумма `n + (n-1) + ... + 1 = n(n+1)/2`, поэтому время работы `O(n²)`. Временный стек может содержать до `n` элементов, память `O(n)`. Это и есть ответ на вопрос об оценке времени.

## Задание 3.3. Первый больший элемент справа

**Файл:** `src/task3_3.cpp`. **Пример входа:** `numbers.txt`.

### Точная формулировка

Для каждого значения `aᵢ` нужен **минимальный номер `j > i`**, для которого `aⱼ > aᵢ`. То есть ищется **первое** большее число справа, а не наибольшее из всех чисел справа. В условии все числа различны. Требуется `O(n)` времени и амортизационное доказательство.

Программа читает файл через `std::ifstream input(path)`: `ifstream` — поток чтения из файла. В `main(int argc, char* argv[])` переменная `argc` сообщает число аргументов командной строки, а `argv` хранит их текст; если имя файла передано, берётся `argv[1]`, иначе используется `numbers.txt`. Сначала из файла читается `n`, затем `n` целых чисел в `std::vector<long long> a`. `vector` — изменяемый по размеру массив стандартной библиотеки, `long long` — целочисленный тип.

### Идея ожидающих индексов

`answer` изначально заполнен нулями. `pending` хранит **индексы** элементов, для которых первый больший справа ещё не появился. `pending.back()` возвращает последний, то есть верхний индекс; `pending.pop_back()` убирает его; `pending.push_back(j)` кладёт новый индекс.

Читаем `a[j]` слева направо. Пока новое число строго больше значения на вершине стека, записываем для этого прежнего индекса ответ `j + 1` и убираем индекс из стека. `j + 1` нужен потому, что индексы внутри C++-массива начинаются с **нуля**, а ответы выводятся с **единицы**. После удаления всех меньших вершин текущий индекс добавляется в стек. Значения элементов на ожидающем стеке остаются невозрастающими.

Почему ответ именно ближайший: позиции `j` рассматриваются по порядку. Если индекс `i` всё ещё ждёт, ни одна более ранняя позиция справа не содержала числа больше `a[i]`; иначе `i` уже был бы извлечён. Первый `j`, который извлечёт `i`, и есть минимальный подходящий индекс.

### Пример

Файл `numbers.txt` содержит `6`, затем числа `2 1 5 3 4 6`.

| Позиция `i` | Значение | Первый больший справа | Ответ `j` |
| ---: | ---: | ---: | ---: |
| 1 | 2 | 5 | 3 |
| 2 | 1 | 5 | 3 |
| 3 | 5 | 6 | 6 |
| 4 | 3 | 4 | 5 |
| 5 | 4 | 6 | 6 |
| 6 | 6 | отсутствует | 0 |

Вывод: `3 3 6 5 6 0`. Ноль у последнего элемента остаётся потому, что большего числа справа нет.

### Амортизационное доказательство `O(n)`

Внешний цикл выполняется `n` раз. Внутренний `while` иногда извлекает сразу много индексов и потому выглядит вложенным циклом `O(n²)`. Но каждый индекс добавляется в стек **ровно один раз** и извлекается **не более одного раза за всю программу**. Всего добавлений `n`, всего извлечений не больше `n`; остальные действия на каждом шаге постоянны. Значит, суммарное время `O(n)`, а амортизированная стоимость обработки очередного элемента `O(1)`. Массив значений, массив ответов и стек занимают `O(n)` памяти.

### 1.5. Почему `map` представляет матрицу без хранения нулей

Пусть `M` — словарь `std::map<std::pair<int,int>, double>`, а `(r,c)` — координата клетки. Соглашение представления такое: если ключ `(r,c)` есть в `M`, значение клетки равно `M[(r,c)]`; если ключа нет, значение равно нулю. **Инвариант:** в словаре находятся ровно ненулевые клетки введённой матрицы. Благодаря ему данные в `map` однозначно задают всю матрицу, даже если большинство клеток отсутствует физически.

При чтении очередного числа программа добавляет ключ только при `value != 0.0`. Поэтому после обработки первых `t` клеток инвариант верен для этих `t` клеток; следующая клетка сохраняет его независимо от того, нулевая она или нет. После чтения всех клеток инвариант верен для всей матрицы. При печати `find({row,column})` ищет ключ: найденная запись даёт число, `end()` означает ноль. Печать проходит **все** координаты, хотя хранится только часть значений.

Замена имеет два случая. Если новое значение ненулевое, `matrix[position] = new_value` создаёт ключ либо перезаписывает старое значение. Если новое значение ноль, `erase(position)` удаляет ключ, даже если его и не было. В обоих случаях после замены инвариант снова верен. Например, для исходной матрицы `2.2 0 7 / 0 0 0 / 0 2.3 0` замена `(1,1)` на `5.5` увеличивает `matrix.size()` с 3 до 4, а замена `(0,2)` на 0 уменьшила бы его с 3 до 2.

`std::map` обычно реализован сбалансированным деревом поиска. Каждое `find`, присваивание по ключу и `erase` занимают `O(log k)` для `k` сохранённых записей. Чтение обычной матрицы размера `R×C` выполняет `R·C` шагов, а печать — `R·C` поисков, то есть `O(R·C·log(k+2))` времени. Память для узлов словаря — `O(k)`. `sizeof(matrix)` показывает только размер управляющего объекта `map`, а **не** сумму размеров выделенных узлов. Значение `matrix.size()` отвечает на другой вопрос — сколько ненулевых клеток хранится.

### 2.3. Три порядка без трёх копий студентов

Один `Node` содержит студента и три независимые ссылки `next[0]`, `next[1]`, `next[2]`. В каждой цепочке узлы те же самые, меняется только порядок. Для каждого ключа `k` поддерживается инвариант: начиная с `sentinel_.next[k]`, можно обойти **все** узлы ровно один раз в неубывающем порядке выбранных полей и вернуться к `sentinel_`. Пустая цепочка тоже удовлетворяет этому правилу: её первая ссылка сразу ведёт к `sentinel_`.

При вставке нового `node` переменная `before` сначала указывает на фиктивный узел. Пока следующий реальный узел строго меньше нового по выбранному ключу, `before` сдвигается. Когда цикл закончился, `before` — последний узел, который должен идти **до** нового; прежний `before->next[k]` — первый узел, который должен идти **после** него, либо фиктивный конец. Две операции `node->next[k] = before->next[k]` и `before->next[k] = node` встраивают новый узел между ними. Остальная цепочка не меняется, значит, порядок сохраняется. Тот же процесс повторяется независимо для каждого из трёх ключей.

Например, студенты `Anna` (группа 22) и `Boris` (группа 21) идут как `Anna → Boris` по имени, но как `Boris → Anna` по группе. Узлы `Anna` и `Boris` при этом существуют в памяти по одному разу. `std::tie` задаёт полный порядок: при равенстве основного поля сравниваются дополнительные поля, затем уникальный `serial`. Поэтому место вставки определено и при совпадающих именах или группах. Строка даты `YYYY-MM-DD` сравнивается правильно только при корректном одинаковом формате дат.

Для `print(k)` не нужно снова сортировать студентов: нужный порядок уже построен ссылками `next[k]`. Печать посещает `n` узлов за `O(n)`. Вставка может просмотреть по `n` узлов три раза, то есть `3n`, что асимптотически `O(n)`; память — `O(n)` узлов и три ссылки на узел. Деструктор удаляет узлы по одной цепочке: удаление по всем трём привело бы к повторному `delete` тех же адресов. Это объясняет и запрет копирования класса.

### 3.1. Массив как память для двусвязного списка

Есть два различных порядка: **физический** порядок ячеек `slots_[0], slots_[1], ...` и **логический** порядок обхода через поле `next`. Например, значения `10,20,30` могут лежать в ячейках `5,1,7`, но связи задают `5 → 1 → 7`. Поля `head_` и `tail_` обозначают концы логической цепочки. Индекс `-1` означает отсутствие соседа.

Инвариант занятой части: если `slots_[i].next == j`, то `slots_[j].prev == i`; у головы `prev == -1`, у хвоста `next == -1`; ровно `size_` ячеек имеют `used == true` и достижимы от `head_`. Отдельный инвариант свободной части: начиная с `free_` по полям `next` можно пройти все и только свободные ячейки. У свободной ячейки `next` означает **следующую свободную ячейку**, а не соседа в пользовательском списке. Одна ячейка не может находиться сразу в обеих цепочках.

`acquire` снимает вершину свободной цепочки, очищает старые связи и делает ячейку занятой. `insert_after` связывает три места: старый узел `position`, новый `id` и старого последователя `following`. Если последователя не было, меняется `tail_`. `insert_before` симметрично меняет `head_`, когда вставка идёт перед первым элементом. `erase` сначала соединяет прежнего и следующего соседей **друг с другом**, а потом помечает удалённую ячейку свободной и кладёт её на вершину `free_`. В каждом случае остальные связи не меняются, поэтому оба инварианта сохраняются.

Пример: `head_=0`, связи `0 ↔ 2 ↔ 1`, значения `1,2,3`. После `erase(2)` узлы 0 и 1 соединяются напрямую, а `free_=2`. Следующая вставка может получить индекс 2 для **другого** значения. Поэтому сохранённый клиентом индекс удалённого узла уже нельзя использовать как постоянный идентификатор старого элемента.

При известном индексе операции меняют постоянное число полей: `O(1)` без расширения. `find` сам ищет индекс, поэтому стоит `O(n)`. Когда свободных ячеек нет, `grow` переносит все `C` старых ячеек в массив ёмкости `2C`, что стоит `O(C)`. Но до следующего роста понадобится заполнить примерно `C` новых ячеек; их обычные дешёвые вставки «оплачивают» перенос. Для длинной серии вставок получается `O(1)` **амортизированно**, хотя одна конкретная вставка может стоить `O(n)`. Индексы переживают рост, потому что ячейка с номером `i` копируется в ячейку с тем же номером `i`.

### 3.2. Почему два прохода по стеку действительно выбирают максимум

В начале итерации `remaining` элементов лежат в `input`; уже выбранные максимумы лежат ниже временной рабочей области `selected`. Первый проход переносит ровно `remaining` значений в `selected` и одновременно вычисляет их максимум. Стек меняет порядок при переносе, но максимум от порядка не зависит. Переменная `first` делает первым максимумом первое реально прочитанное число, поэтому алгоритм работает даже для `-8,-3,-5`.

Второй проход снимает с `selected` **ровно столько же** временных значений. Одну встреченную копию `maximum` он не возвращает, остальные возвращает в `input`. Переменная `skipped` не позволяет случайно убрать две одинаковые копии. После этого `maximum` кладётся поверх уже выбранных элементов `selected`. Инвариант следующей итерации восстановлен: в `input` осталось на один элемент меньше, а `selected` содержит на один правильно выбранный максимум больше. Более старые элементы `selected` не затрагиваются, потому что снимается точно `remaining` временных значений.

Для `4,-2,7,4,1` максимумы выбираются в порядке `7,4,4,1,-2`. Если читать `selected` **снизу вверх**, это убывающий порядок. Но стек выдаёт значения **сверху вниз**, поэтому `Pop()` напечатает `-2,1,4,4,7` по возрастанию. Каждый выбор обрабатывает `remaining` элементов дважды. Сумма `2(n+(n-1)+...+1) = n(n+1)`, следовательно, время `O(n²)`, дополнительная память второго стека `O(n)`. `Pop()` вызывается только тогда, когда по счётчику в соответствующем стеке есть элемент; сам метод `Pop()` не проверяет пустоту.

### 3.3. Почему монотонный стек находит именно первого большего справа

После обработки позиций `0...j-1` в `pending` лежат индексы, для которых ответ ещё неизвестен. Они идут по возрастанию индексов от низа к верху, а их значения `a[index]` идут **невозрастающе**. Это инвариант. При приходе `a[j]` оно снимает с вершины все строго меньшие значения. После этого оставшаяся вершина, если есть, не меньше `a[j]`; добавление `j` снова даёт невозрастающий стек. Равное значение не снимается, потому что требуется **строго** большее.

Трассировка для `2,1,5,3,4,6` (в таблице индексы показаны с единицы):

| Новое число | Какие ожидания оно завершает | Ожидающие значения после шага |
| --- | --- | --- |
| `2` на позиции 1 | никого | `2` |
| `1` на позиции 2 | никого | `2,1` |
| `5` на позиции 3 | `1 → 3`, `2 → 3` | `5` |
| `3` на позиции 4 | никого | `5,3` |
| `4` на позиции 5 | `3 → 5` | `5,4` |
| `6` на позиции 6 | `4 → 6`, `5 → 6` | `6` |

Почему найденный индекс ближайший? Позиции рассматриваются строго слева направо. Если старый индекс `i` ещё лежит в `pending` перед позицией `j`, все позиции между `i` и `j` уже прочитаны и ни одна не была больше `a[i]`; иначе `i` сняли бы раньше. Если `a[j] > a[i]`, текущая позиция `j` — первая подходящая. Индексы, не снятые до конца массива, получают оставшийся начальный ответ `0`.

Оценка `O(n)` получается не из одного шага `while`: на одном шаге он может сделать много извлечений. Вместо этого считаем действия за **всю** программу. Каждый индекс добавляется ровно один раз и снимается не более одного раза. Значит, всего не более `n` добавлений и `n` извлечений, плюс `O(n)` работы внешнего цикла. Память массивов `a`, `answer` и `pending` — `O(n)`.
